# LTX Director 2.0 — Integrated Features

This document covers the local features integrated **on top of** the upstream
"LTX Director 2.0" rewrite. Each was either reworked to fit 2.0's new architecture or
re-applied because 2.0 dropped it. For the unchanged auxiliary nodes (LTX Sequencer,
Keyframer, Multi Image Loader, etc.) see [nodes.md](nodes.md).

> **Doc debt:** `architecture.md` and `ltx-director.md` (on the `chore/dev-skill-and-docs`
> branch) describe the **pre-2.0** internals and are now stale. They need a separate
> rebase-onto-2.0 + rewrite pass; this file intentionally documents only the integrated
> features, not the full 2.0 architecture.

## 0. Timeline Save / Load (server-side) — `ltx_director_timeline.py`, `js/ltx_director.js`

2.0's Save/Load used the browser **File System Access API** (`showSaveFilePicker`), which
some browsers — notably **Brave** — disable by default, so Save re-prompted every time and
could never silently overwrite. Replaced with server-side persistence:

- Backend routes `POST /ltx_director/save_timeline`, `GET /ltx_director/list_timelines`,
  `GET /ltx_director/load_timeline` write/read JSON under
  `<user_dir>/ltx_director_timelines/` (falls back to the output dir). Names are
  basename/charset-sanitised and asserted to resolve inside that folder (same hardening as
  the bundle routes).
- **Save** posts `_getTimelineSavePayload()` under a remembered name (`node._ltxTimelineName`)
  — only the first save prompts for a name; afterwards it's silent. **Shift-click Save =
  Save As** (prompt for a new name). **Load** lists saved timelines in a picker modal.
- Works in any browser, independent of the File System Access API.
- **No binary in the JSON.** A `JSON.stringify` replacer (`_stripInlineBase64`) drops any
  `data:` `imageB64` value at every persistence point (the `timeline_data` widget *and* the
  Save/bundle payload). `imageB64` is only a regenerable thumbnail cache — video clips
  rebuild it from the file via `_ensureVideoEl` on load, and the backend reads the media
  file, never the thumbnail — so embedding base64 just bloated the JSON and every prompt
  payload (≈86% of a real export in one measured case). `/view` path references are kept;
  legacy timelines self-heal on the next save.

## 1. File-route path-validation (security) — `load_video_ui.py`

The 2.0 rewrite reintroduced two unvalidated HTTP routes; this re-applies the hardening.

- **`GET /video_ui_custom_view`** — previously served *any* file on disk by absolute
  path. Now normalises with `os.path.realpath` and restricts served files to a media
  extension allow-list (`_ALLOWED_PREVIEW_EXTS`). The "preview media by absolute path"
  feature is preserved; arbitrary file read (SSH keys, `.env`, source) is not.
- **`POST /video_ui_upload_chunk`** — previously wrote a client-supplied filename via
  `os.path.join` (path traversal). Now basename-strips the name, validates chunk metadata,
  asserts the resolved path stays inside the upload dir (`os.path.commonpath`), and returns
  the sanitised name. As of upstream v2.0.4 the upload dir itself moved from
  `input/whatdreamscost/` to root `input/`, so the returned name is the plain sanitised
  filename (no `whatdreamscost/` prefix) — updated to match during the 2026-09-05 resync.

## 2. Portable timeline bundle (zip) — `ltx_director_bundle.py`, `__init__.py`, `js/ltx_director.js`

Layers a portable bundle **on top of** 2.0's existing timeline Save / Save As / Load
(which reference media by filename only). A bundle packages the timeline JSON together
with its actual media so a timeline can be backed up or shared and restored on a fresh
install.

- **Routes** (registered from `__init__.py`):
  - `POST /ltx_director/save_bundle` — body is the exact payload from the editor's
    `_getTimelineSavePayload()` plus a `bundleName`. Zips `timeline.json` + `media/<rel>`
    for every referenced file and streams it back as a download.
  - `POST /ltx_director/load_bundle` — extracts media into `input/<bundleName>/`
    (create-or-overwrite), re-points every media reference to that subfolder, and returns
    the re-pointed manifest.
- **2.0 data model handled:** media refs are collected/re-pointed across `segments` and
  `motionSegments` (`imageFile`, `videoFile` — note main-track *video* uses `imageFile`),
  `audioSegments` (`audioFile`), and `retakeVideo` (`imageFile`). Because the editor
  splits each ref into `filename` + `subfolder` for its `/view?type=input` URL, a nested
  ref like `whatdreamscost/foo.mp4` simply gains the bundle prefix and keeps resolving.
- **Security:** mirrors the `load_video_ui.py` patterns — input-dir containment on save,
  and on load a sanitised bundle name, media-extension allow-list, and per-entry zip-slip
  containment assertion before writing.
- **UI / single code path:** "Export Bundle" / "Import Bundle" buttons in the timeline
  settings grid. Export posts `_getTimelineSavePayload()`; Import feeds the returned
  manifest straight back through 2.0's `_applyLoadedTimeline()`, so bundle and plain
  Save/Load share one serialize/hydrate path.
- **Backward compatibility (pre-2.0 bundles):** `load_bundle` calls
  `_migrate_legacy_manifest()` on any bundle marked `format: "ltx-director-timeline"`,
  normalising it to the 2.0 shape before media is re-pointed: the global prompt is lifted
  from `settings` to the top level, and old main-track video segments (which stored the
  file in `videoFile` with no `imageFile`) get `imageFile = videoFile` with their stale
  `frames`/`imageB64` dropped so 2.0 rebuilds the preview. On the JS side,
  `_rehydrateBundleThumbnails()` rebuilds each image segment's `imageB64` from the
  re-pointed `imageFile` (2.0 builds previews from `imageB64` and does not rebuild them
  from `imageFile` on load); this also fixes stale `/view` thumbnails in *new* bundles.
  Verified with a unit test over a synthetic old manifest.

## 3. Clip type conversion — `js/ltx_director.js`

Right-click a main-track clip to change its kind in place, preserving start/length/prompt
(2.0 had Replace / End-Frame for image clips but no type switch):

- Image clip → **"Remove Image (→ Text)"**, **"Add Video (→ Video)…"**.
- Text clip → **"Add Image (→ Image)…"**, **"Add Video (→ Video)…"**.
- Video clip → **"Remove Video (→ Text)"**, **"Replace with Image (→ Image)…"**, and
  **"Replace Video with…"**. Video clips also get **"Set Guide Stride…"** (see §4).

"Add Video"/"Replace Video with…" all reuse the standard import pipeline (upload +
thumbnail + duration + linked audio): the existing clip (and its linked `_a` audio sibling,
if any) is removed and the chosen video re-imported at the same start, **carrying the
clip's prompt over** (an optional prompt threaded through `handleVideoUpload`). The new
clip's length is the imported video's natural length.

Helpers `_attachImageToSegment` / `_convertSegmentToText` / `_pickImageForSegment` /
`_clearVideoFields` / `_replaceVideoOnSegment` follow 2.0's existing `/upload/image` +
`"whatdreamscost"` convention and the video upload path; the buttons sit in a new group in
`showContextMenu` between End-Frame and Unlink. `guide_strength` self-heals via
`commitChanges()` (text segments already excluded). `_clearVideoFields` strips video-only
keys so image/text conversions don't leave stale video state.

## 4. `video_guide_stride` — guide density for video clips — `ltx_director_guide.py`, `ltx_director.py`

Pins only every Nth encoded latent frame of a video clip as an anchor and lets the model
interpolate the gaps. Without it, a video's frames are pinned at every latent frame, which
**stair-steps on short extensions**. Applies to **two paths**:

- **Extension ("A" image-guide path)** — the common case (placing a video on the main
  track to continue it). 2.0 pinned every encoded latent frame at the clip's `strength`
  with no per-frame mask. Now the A-branch builds a per-frame `guide_mask` for multi-frame
  (video) guides and thins it by the effective stride; **segment endpoints (first/last)
  stay anchored** so the extension joins cleanly. Per-clip values are plumbed via
  `guide_data["strides"]` from `ltx_director.py`.
- **IC-LoRA motion ("B" path)** — same idea on the contiguous motion-segment `guide_latent`
  (keeps frame 0 + boundary-ramp frames).

**Control (per-clip + global default):**
- **Global default** — `video_guide_stride` node input (default `1`, 1–64) on
  `LTXDirectorGuide`. `1` = pin every frame (stock behavior).
- **Per-clip override** — `seg.videoGuideStride`, set from a video clip's right-click
  **"Set Guide Stride…"**. Blank/0 inherits the default; effective stride =
  per-clip when ≥1, else the node default.

> Note: the global default lives on the **Guide** node (where the masking happens); the
> per-clip override lives in the **timeline editor** (the clip menu). A side-panel field
> for the per-clip value is a possible future polish (the menu prompt is the current UI).

## 5. `audio_blend_secs` (audio boundary crossfade) — `ltx_director.py`

Re-implemented because 2.0 dropped it and its audio noise mask hard-steps at segment
borders. In the custom-audio path 2.0 builds a 3D `gap_mask` that is `1.0` (free
generation) everywhere and `0.0` (preserve encoded audio) across each audio segment, so
at a segment's trailing edge into a region with no audio the mask jumps `0 → 1` instantly
— an audible cut.

- New optional node input **`audio_blend_secs`** (default `1.0` s) on `LTXDirector`,
  surfaced in the timeline settings (gear) menu as **"Audio Blend (s)"** and managed like
  the other settings widgets (`_settingsWidgetNames`), so it's hidden on the node face and
  toggled by Show/Hide Widgets.
- In the non-retake mask loop, after a segment's span is set to `0.0`, the mask is tapered
  `0 → 1` over the last `blend_frames = round(audio_blend_secs · F_len / total_sec)`
  latent positions, so preserved audio fades into freely-generated audio. `0` keeps 2.0's
  hard boundary.
- Applies to both `audioSegments` and (with `override_audio`) `motionSegments`; the
  retake-mode mask is unaffected.
- Because it's a director-node widget, 2.0's save/load and the bundle round-trip
  serialize/restore it automatically — including the value carried in old bundles'
  `settings.audio_blend_secs`.
- Verified with a unit test: at `1.0` s the largest adjacent mask step drops from `1.0`
  (stock) to `0.14` and the trailing ramp is monotonic; at `0` the hard boundary is
  preserved.
